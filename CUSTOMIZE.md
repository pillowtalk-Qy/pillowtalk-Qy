# Customize NULL//SELF

## Public GitHub cover

Review the identity copy in `README.md`:

- Confirm the `Qy` display name and `pillowtalk-Qy` GitHub/Pages URLs.
- Add a PGP fingerprint only after publishing the corresponding key.
- The three public-surface lines, if they do not describe your real work.
- The static evidence ledger so its grades match the sources you actually publish.

The root `README.md` is the Profile README. Keep the `game/` directory as the GitHub Pages application; the README link is its entry point because GitHub does not execute JavaScript, WebCrypto, WebAssembly, or Three.js inside profile Markdown.

## GitHub-native proof protocol

`profile/challenges.json` defines the three README proof vectors and the real project capsule attached to each one. `profile/state.json` is shared public state. Never edit the generated block between `PROFILE-PROTOCOL` markers manually; regenerate it with:

```bash
node profile/scripts/render-profile.mjs
```

`profile-proof.yml` treats Issues as visitor input and commits valid state transitions back to the README. The first two vectors verify owner-provided public evidence. Hashcash is bound to the visitor's public GitHub login and requires a nonce generated by `game/public/mint.html`.

The displayed nullifier is pseudonymous, not anonymous. GitHub Issues, comments, commits, and Action logs remain public. The capsules are narrative reveals, not access control; never place secrets behind them.

## Replace the demo evidence

Evidence nodes and their honest scope live in `game/src/evidence.ts`. Before deployment:

- Point public artifacts at real files, releases, deployments, or chain records.
- Recompute every declared SHA-256 digest after replacing a file.
- Replace the demo Merkle manifest with actual project metadata.
- Leave a node as `SOURCE MISSING` when no independent source exists; do not upgrade a self-attestation by wording alone.

The bundled Circom artifact is copied to `game/public/evidence/redacted_archive.circom` so the deployed byte stream can be hashed in the browser.

## Signed owner claims

Edit the statements and evidence strings in `game/src/profile.ts`. A changed message must receive a new Ed25519 signature; never retain a signature from the previous text.

## Encrypted project capsules

Edit `game/protocol/protocol.content.json` to change:

- The three project capsules and their visible evidence chains.
- The Merkle project choices and committed leaf.
- The final 2-of-3 dossier, frontiers, and contact channel.

Then regenerate all cryptographic material:

```bash
cd game
npm run protocol:generate
npm run build
```

The command replaces `game/src/generated-protocol.ts` with fresh ciphertext, salts, IVs, Shamir shares, and Merkle data.

## Zero-knowledge policy

Policy `1049` proves only that the visitor selected no more than one local signal. Changing that statement requires rebuilding the Circom circuit, WebAssembly, proving key, verification key, and Issue verifier together.

## Deployment scope

The bundled version is static and safe only for public information presented as an interaction. Use a backend key-share issuer before treating completion as authorization or placing sensitive material behind a capsule.
